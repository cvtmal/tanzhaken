# #11 account-and-reset — outcome (2026-11-11)

## Delivered
Forgot/reset password by emailed link (ACC-3) and the `/account` settings page (ACC-4). A teacher asks for a link on `/forgot-password`; the answer is the same for known, unknown and rate-limited emails (no enumeration). The plain-text mail carries a single-use link, valid 60 minutes, built from `DEFAULT_URI`. The link page sets a new password, deletes all of that teacher's links, logs out the teacher's other sessions, and sends the teacher to `/login` with an info alert. `/account` has a Profile card (display name, time zone), a Password card (current + new), the logout form for phones (D-033), and an empty slot for #18. New: one table, one migration, one env variable, two limiters, one stylesheet. Placeholder actions `passwordForgot`, `passwordReset`, `account` are gone (`privacy` stays for #18).

## Interfaces
- **Routes:** `password_forgot` GET|POST `/forgot-password` (logged in → `dashboard`); `password_reset` GET|POST `/reset-password/{token}` (works logged in or not; invalid/expired/used → 404 page with a "Request a new link" button); `account` GET `/account`; `account_profile` POST `/account/profile`; `account_password` POST `/account/password` (invalid form → 422 re-render, success → PRG to `/account` with a toast). Every response of `password_reset` sends `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`, `Cache-Control: no-store`.
- **Table `password_reset_request`** (final name, for #18 and #21), migration `Version20261111081441` (SQLite + MariaDB, with `down()`): `id` uuid PK; `teacher_id` uuid FK → `teacher(id)` ON DELETE CASCADE, index `idx_password_reset_request_teacher`; `token_hash` CHAR(64), unique `uk_password_reset_request_token_hash`; `requested_at`, `expires_at` (UTC). No `used_at`: used and superseded rows are deleted; an expired row is refused and stays until the teacher's next request or reset (no purge).
- **Services (`App\Account\Service`):** `PasswordResets::request(string $email): void` (never throws), `findValid(string $token): ?PasswordResetRequest`, `reset(string $token, string $newPassword): void` (throws `Exception\InvalidResetLink`); `AccountSettings::updateProfile(Teacher, ProfileData): void`, `changePassword(Teacher, string $newPassword): void`; `ResetTokens::issue(): IssuedResetToken` (`plain`, `hash`), `hash()`, `isWellFormed()`; `ResetLinkGenerator::forToken(string): string`; `ResetMailer::send(Teacher, string $resetUrl, int $validMinutes)`; `PasswordResetThrottle::allowIp(string)`, `allowEmail(string)` (`?DateTimeImmutable` retry-after, null = allowed); `DeferredMailer::queue(Email)`, `sendQueued()` (`kernel.terminate`, `kernel.reset`).
- **Repository:** `PasswordResetRequestRepository::findOneByTokenHash(string)`, `deleteForTeacher(Teacher)`.
- **Audit events:** `teacher.password_reset`, `teacher.profile_updated` (details `changed`), `teacher.password_changed`. The request itself is not audited.
- **Config / env:** `config/packages/rate_limiter_account.yaml`: `password_forgot_ip` sliding window 10 / 15 min (refusal: 429 + alert), `password_forgot_email` 3 / 60 min (silent). `MAILER_FROM` in `.env` / `.env.example` (default `no-reply@localhost`).
- **Templates:** `account/forgot_password`, `reset_password`, `reset_password_invalid`, `show`, `email/password_reset.txt.twig`. **CSS:** `assets/styles/account/settings.css` (card gaps on `/account`). **Catalogues:** `account` `forgot.*`, `reset.*`, `email.password_reset.*`, `settings.*`; `validators` `account.forgot.*`, `account.settings.*`.

## How to use it
- **#18 deletion:** create `templates/account/_delete.html.twig`; `account/show.html.twig` already ends with `{% include 'account/_delete.html.twig' ignore missing %}`. Deleting a teacher removes its reset rows by FK cascade.
- **Tests that POST `/forgot-password`:** call `resetLoginThrottling($client)` first (it clears the `cache.rate_limiter` pool that holds both limiters). In a `KernelTestCase`, call `DeferredMailer::sendQueued()` to send queued mail; functional tests see it with `assertEmailCount()`.
- **New mail:** queue it via `DeferredMailer::queue()` and build links with a `DEFAULT_URI` context like `ResetLinkGenerator`, never from the request Host.

## Decisions
- R1 own table, rows deleted when used/superseded/expired (no `used_at`). R2 token = 32 random bytes base64url, sha256 stored, 60 min, one message for malformed/unknown/expired. R3 a reset deletes all the teacher's links and does not log in; a new request supersedes older links. R4 identical PRG answer for every email; mail sent on `kernel.terminate`. R5 two limiters (IP shown, email silent); none on the token URL. R6 link host from `DEFAULT_URI`. R7 no-referrer/noindex headers, self-hosted assets only. R8 text-only `TemplatedEmail`, sender `MAILER_FROM`. R9 `/account` with two separately named forms and POST sub-routes. R10 audit only the completed reset. Undo for each: research `account-and-reset` § Selected design details.
- P1 Phase 0 adapts names mechanically, blocks on semantic differences (none found). P2 IP refusal re-renders with 429. P3 invalid link answers 404 (undo: status in `PasswordResetController::reset`). P4 auth-layout flashes use `info` (no `toast.js` there). P5 a settings password change also deletes pending reset links. P6 new-password messages reuse `account.register.password.*`. P7 logged-in visitors on `/forgot-password` go to `dashboard`; the reset link works logged in.

## Deviations
- `ProfileData` created in Phase 2 (needed by `AccountSettings`). `updateProfile()` checks empty/too-long name before the transaction (D-027); `request()` swallows `InvalidTeacher` from bad input. MariaDB branch is Doctrine's dump (utf8mb4, no explicit engine).
- Unplanned catalogue keys (labels, help, page texts, mail subject "Reset your {brand} password"); extra blank lines in the mail; R7 headers also on the success redirect.
- Fix: `deleteForTeacher()` now binds the id with `UuidType::NAME` (the entity parameter matched nothing, so used links stayed valid); covered by tests 6.2–6.4.
- Step 5.5 was skipped on the belief that `card.css` gives cards an outer margin; it does not (that line is `--card-pad`). The 7.3 browser check showed the two cards touching and titles flush on their forms, so `settings.css` was added (tokens only, scoped by form name, no template change).

## Carried forward

- Mail timing: `DeferredMailer` sends on `kernel.terminate`. Under PHP-FPM, `Response::send()` calls `fastcgi_finish_request()` (also `litespeed_finish_request()`) before terminate, so the response is complete before SMTP starts. On other SAPIs it only flushes buffers, so known and unknown emails may still differ in timing (checked in `vendor/symfony/http-foundation/Response.php:409-414`; research covered only testability) → #19.
